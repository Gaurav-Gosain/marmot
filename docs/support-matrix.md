## Build modes

- **dev** (default, `-O2`): the safe pipeline; every transform below that is marked off stays off.
- **`-release`**: whole program optimization, `-O3`, loop and library specializations.
- **`-O0` `-O1` `-O2` `-O3` `-Os` `-Oz`**: LLVM level; the conformance runner can run any program in `-O0`, `-O2`, `-Oz` and `-release` (`-modes`).
- **Opt-in lifetime and memory transforms**, each behind an environment switch. A transform is on by default only after a proof review and a full conformance matrix plus fuzz round with it forced on; until then it is off.

## Known differences from gc

- Panic output prints the same message and exits with status 2; the traceback below `goroutine N [running]:` is gc style but frames of inlined functions do not appear.
- Floating point uses the same fused multiply-add rule as gc on arm64 (`x*y+z` fuses, an explicit conversion does not).
- Variables are read after calls in the same expression, as gc does (the spec leaves this unspecified).
- `runtime.Caller` and friends work from a pc table; binaries built with `-s` have none.
- **NaN payloads.** Where the Go specification only says the result is a NaN, marmot may return a different NaN (payload and sign bits) than gc: the builtin `min` and `max` (also over slices, so `slices.Min` and `slices.Max`), `math.Max`, `math.Min`, and `math.Floor`, `Ceil`, `Trunc`, `Round` and `RoundToEven` of a signaling NaN (gc quiets it, marmot may return it unchanged). The value is a NaN in every case; only `math.Float64bits`, `math.Float32bits` or `unsafe` shows the difference, and gc itself differs here across architectures. Values that are not NaN are bit identical to gc on the same architecture; a difference there is a bug. Programs: `tests/run/audit/minmax_nan_payload`, `tests/run/audit/math_exp_log_bits`.
- Slice growth capacities and map iteration order are not guaranteed to equal gc's.
- Evaluation order: variables are read after the calls of the same expression; open cases are tracked in `tests/run/audit/evalorder_gaps`.
- Unexported methods of embedded types from different packages with the same name: see `world/audit_unexported` under open failures.
- The race detector, plugins, DWARF and Windows are not supported.
- `reflect`: see the open failures below for the current gaps.
